# Stylebase 底部 Codex 队列美化计划（V3）

## 1. 本轮目标

使用已经确认的四张角色资产，重构底部 Codex 队列栏的视觉层级，使其接近最初批准设计中的“角色工作队列”，同时保持队列轮询、状态排序、展开收起、错误重试和进度展示等功能不变。

本轮只修改底部队列，不处理顶部导航、左侧导航、中央素材区和右侧检查器。

## 2. 已锁定角色资产

以下四张透明 PNG 已经由用户确认，本轮直接使用，不重新生成、不覆盖：

| 任务状态 | 资产 |
| --- | --- |
| 分析中 | `public/assets/illustrations/queue-roles-v1/queue-role-analyzing.png` |
| 等待中 | `public/assets/illustrations/queue-roles-v1/queue-role-waiting.png` |
| 已完成 | `public/assets/illustrations/queue-roles-v1/queue-role-complete.png` |
| 错误 | `public/assets/illustrations/queue-roles-v1/queue-role-error.png` |

资产规格：512×512、透明背景。显示尺寸由 CSS 控制，源文件保持不变。

状态映射：

- `queued`、`pending` → 等待角色。
- `running`、`processing`、`analyzing` 及其他活动状态 → 分析角色。
- `complete`、`completed`、`ready` → 完成角色。
- `failed`、`needs_setup` → 错误角色。

## 3. 当前问题

1. 当前队列摘要占据左侧固定区域，任务卡片被挤压，和原设计稿的横向工作队列差异较大。
2. 角色只有约 42px，退化成状态图标，无法成为设计稿中的视觉主角。
3. 卡片同时展示标题、阶段、进度、日期、缩略图和角色，信息拥挤。
4. 四种状态主要依赖文字与进度条颜色，卡片轮廓和节奏缺少差异。
5. 移动端进一步压缩为 34px 角色，识别度不足。
6. 横向滚动条权重过高，队列更像数据表而不是手绘工作台。

## 4. 唯一设计方向

### 4.1 整体结构

将底部队列改为两行结构：

```text
┌ Codex 队列  [4]   2 项执行中 · 1 项等待                  重试 / 展开 ↑ ┐
│ [缩略图 任务信息 角色] [缩略图 任务信息 角色] [缩略图 任务信息 角色] → │
└───────────────────────────────────────────────────────────────┘
```

- 第一行是 32–36px 的队列摘要条，贯穿整个底部。
- 第二行是横向任务卡片轨道。
- 收起高度目标：132–140px。
- 展开后维持现有多行/滚动能力，高度不超过约 42vh。

### 4.2 摘要条

- 左侧：队列图标和“Codex 队列”。
- 活动数量改成黄色手绘数字徽章，不再独占大面积。
- 中部：简短状态摘要，例如“2 项执行中 · 1 项等待”。
- 右侧：异常重试和展开/收起。
- 摘要条使用暖白纸张背景、深色下划线和极轻铅笔纹理。
- 保留现有 `#queue-toggle` 的 button 语义和 `aria-expanded`。

### 4.3 任务卡片

桌面目标尺寸：

- 宽度：230–250px。
- 高度：84–92px。
- 缩略图：54–58px × 68–72px。
- 角色：58–66px。
- 内部网格：`缩略图 / 信息 / 角色`。

信息优先级：

1. 素材标题，最多两行。
2. 当前阶段和百分比。
3. 进度条。
4. 错误摘要仅在错误状态出现。

日期和次要技术信息在收起状态隐藏，展开状态再显示。

### 4.4 四种状态

| 状态 | 主色 | 卡片表现 | 角色表现 |
| --- | --- | --- | --- |
| 分析中 | 钴蓝 | 蓝色顶线、蓝色进度、轻量扫描纹 | 分析角色轻微呼吸 |
| 等待中 | 黄色 | 黄色虚线角标、中性进度底槽 | 时钟左右摆动一次 |
| 已完成 | 绿色 | 绿色完成印章、满进度条 | 完成角色进入时弹跳一次 |
| 错误 | 红色 | 红色边角、单行错误摘要 | 错误角色警示灯闪一次 |

动画只在状态变化或活动任务上运行，不让所有角色持续晃动。必须支持 `prefers-reduced-motion`。

### 4.5 手绘细节

- 2px 石墨色边框。
- 轻微不对称圆角，避免每张卡片随机旋转。
- Hover 上移 1px，Active 回落。
- 角色可以越过卡片顶部 3–5px，但不得被轨道裁切。
- 进度条保持代码绘制，不生成成图片。
- 不增加新的贴纸、胶带、咖啡渍或角色素材。

## 5. 技术路线

继续使用当前原生 JavaScript，不引入 React、Vue、Lottie、Rive 或 GSAP。

推荐改造：

1. 将状态到角色文件的映射提取为纯函数，例如：
   - `public/queue-role.js`
2. 为映射增加独立单元测试：
   - `tests/queue-role.test.mjs`
3. 保留 `renderQueue()`、轮询和现有数据结构。
4. CSS Grid 负责卡片内部结构。
5. Flex + `scroll-snap` 负责横向队列。
6. CSS 自定义属性负责不同状态的颜色和动效。

不修改后端 API，不修改数据库，不改变 job status 字段。

## 6. 响应式规格

### ≥ 1180px

- 卡片宽 230–250px。
- 角色 58–66px。
- 一屏约显示 5–6 张任务卡片。

### 920–1179px

- 卡片宽 205–220px。
- 角色约 54px。
- 隐藏日期和次要阶段描述。

### 640–919px

- 卡片宽 185–200px。
- 角色约 48–52px。
- 摘要条隐藏详细说明，只保留队列名、数量、异常提示和展开按钮。

### < 640px

- 卡片宽 170–182px。
- 角色约 44–48px。
- 轨道使用横向吸附滚动。
- 所有按钮触控区域不小于 44×44px。
- 不允许角色、标题和进度条互相覆盖。

- 队列轮询正常。

## 9. 验收标准

- 四个确认角色映射正确，无重新生成或替换。
- 角色在桌面端是视觉主角之一，而不是 34–42px 小图标。
- 收起状态一眼能分辨等待、分析、完成和错误。
- 任务标题、阶段、进度和错误信息层级清楚。
- 390–1536px 无重叠、裁切和横向页面溢出。
- 动效克制且可关闭。
- 所有现有测试和功能通过。

## 10. 停止条件

出现以下情况必须暂停：

- 准备重新生成或修改四张已确认角色。
- 准备修改底部队列以外的页面区域。
- 需要改变后端 API、数据库或 job 状态定义。
- 未展示阶段截图就准备继续下一阶段。
- 发现会覆盖其他任务留下的未提交文件。
