# Stylebase 手绘插画改造交接包

## 目标

在不改变现有功能、数据结构、接口和操作流程的前提下，将 Stylebase 改造成“手绘插画 × 涂鸦 × 俏皮”的视觉界面。

最终方向采用：

- 方案 A 的整体构图、素材密度、右侧活页检查器和底部队列。
- 方案 B 的左侧插画导航。
- 插画主要用于导航、品牌、状态反馈与空状态；素材图片始终是内容主角。

## 视觉基准

实现前先打开：

- `final-design.png`：已经确认的桌面端视觉基准。
- `inspiration-sources.md`：项目灵感库中使用过的参考与提炼原则。

设计稿是方向和构图基准，不要求把生成图中的示例素材、虚构数量或示例文案写入产品。实际页面必须继续使用当前 API 返回的真实数据。

## 实施文件

预计只修改：

- `public/index.html`
- `public/styles.css`
- `public/app.js`（仅添加视觉类名或装饰节点）
- `public/assets/`（新增插画与纹理）

明确不修改：

- API 请求和响应格式
- SQLite 数据结构
- Codex 分析与队列逻辑
- 导入、扫描、搜索、筛选、排序、收藏、元数据保存逻辑
- 现有交互元素的 ID 与事件绑定

## 核心设计约束

1. 操作正文使用清晰的系统中文无衬线字体；手写仅用于 Logo、便签和极短批注。
2. 群青蓝用于主操作、焦点和素材选中；黄色主要用于当前导航；红色用于错误；绿色用于完成。
3. 不使用大面积圆角卡片、胶囊按钮、玻璃拟态、渐变或米色奢华编辑风。
4. 手绘感来自插画、墨线、蜡笔圈选、纸张纹理与状态角色，不通过破坏对齐和信息层级制造。
5. 状态必须同时使用文字、形状或图标表达，不能只依赖颜色。
6. 保持键盘操作、可见焦点、移动端检查器和 `prefers-reduced-motion` 支持。
