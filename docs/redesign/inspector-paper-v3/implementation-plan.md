# Stylebase 右侧检查器纸张化美化计划（V3）

## 1. 目标

只改造右侧分析检查器及其章节导航，在不改变数据、分析、收藏、复制、metadata 编辑和移动端返回等功能的前提下，将它从普通白色侧栏改造成“视觉研究活页夹”。

本轮不进行整站重新设计。每完成一个阶段都先截图、验证并确认，再进入下一阶段。

## 2. 已确认的设计方向

- 整体气质：手绘、插画、涂鸦、俏皮，但仍然是一款高效率资料工具。
- 视觉隐喻：插在工作台右侧的视觉研究活页夹，而不是后台抽屉或普通卡片栏。
- 内容优先：真实参考图和分析内容仍是主角，纸张效果只负责建立层次。
- 克制原则：不堆叠咖啡渍、撕纸、胶带、贴纸和大面积装饰。
- 技术原则：允许升级技术栈，但必须证明收益，不为了视觉效果整站迁移 React/Vue。

## 3. 当前问题

1. 四段章节导航已有功能，但仍表现为一排普通按钮。
2. 检查器主体是一张连续白页，衬板、纸页、活页环和分页标签没有形成空间层次。
3. `public/assets/illustrations/binder-rings.png` 只有 182 字节，是占位素材，无法承担主要视觉特征。
4. 预览、视觉 DNA、色票、Prompt 和资料管理使用相近的分隔方式，阅读节奏单一。
5. Prompt 和技术信息容易让面板过长，纸张隐喻会在滚动中消失。

## 4. 推荐成品结构

### 4.1 桌面端

- 检查器宽度目标：常规桌面 376–396px，窄桌面 336–356px。
- 底层：浅棕灰硬纸板衬底，露出 8–12px。
- 主纸页：暖白色，带 3%–6% 的细颗粒纹理和轻微不规则纸边。
- 左侧装订：7–9 个固定活页环；滚动内容时装订结构不漂移。
- 右侧索引：预留约 28px 标签槽，四个彩色纸质索引耳垂直排列。
- 当前章节：索引耳外移 4–6px，并出现铅笔下划线或圈注。
- 顶部：档案标签式标题、状态和关闭按钮，标题最多两行。
- 预览：表现为夹在纸页上的照片，只使用一枚纸夹或一段半透明胶带。

四个章节：

1. 黄色 `概览`：预览、状态、分析摘要、主要操作。
2. 紫色 `视觉分析`：视觉 DNA、色票、为何有效。
3. 蓝色 `实作输出`：Recipe、Prompt Kit、复制操作。
4. 绿色 `资料管理`：来源、收藏集、metadata、技术证据。

### 4.2 移动端

- 检查器继续作为全屏层，不改变现有打开和关闭逻辑。
- 垂直索引耳改为顶部横向纸质分页标签。
- 底部主要操作保持固定，但视觉上改成轻量纸条，不遮挡正文。
- 所有触控目标不小于 44px。

## 5. 素材计划

| 素材 | 方式 | 目标文件 | 要求用户制作 |
| --- | --- | --- | --- |
| 暖白纸张纹理 | 先用 SVG 噪声建立基线，再生成 2 个无缝 WebP 候选进行对比 | `public/assets/inspector/paper-grain-warm.webp` | 否 |
| 活页环 | 手绘矢量 SVG | `public/assets/inspector/binder-rings.svg` | 否 |
| 不规则纸边 | SVG mask | `public/assets/inspector/paper-edge-mask.svg` | 否 |
| 纸夹或胶带 | CSS/SVG | `public/assets/inspector/paper-clip.svg` | 否 |
| 铅笔圈注和箭头 | SVG sprite | `public/assets/inspector/doodles.svg` | 否 |
| 小型分析印章 | SVG | `public/assets/inspector/analysis-stamps.svg` | 否 |
| 四个分页标签 | CSS 形状 | 无独立文件 | 否 |

本轮采用“代码负责结构，素材负责质感”的混合路线。布局、文字、按钮、章节状态、分页标签和响应式必须由 HTML/CSS/JS 实现；纸纤维、铅笔笔触、胶带、纸边和装饰印章可以生成素材。不得把整张检查器或带文字的导航生成成背景图片。

第一版优先使用自产素材。若外部素材明显更好，只允许使用授权明确的 MIT、OFL、CC0 或兼容素材，并在 `docs/redesign/inspector-paper-v3/asset-licenses.md` 记录来源、作者、链接、许可证和使用位置。

## 6. 技术路线

### 路线 A：原生 JS 模块化（本轮推荐）

保留现有状态和事件系统，将右侧检查器从 `public/app.js` 中拆分为可独立测试的渲染模块：

- `public/inspector/inspector-view.js`
- `public/inspector/inspector-navigation.js`
- `public/inspector/inspector.css`

视觉效果使用 CSS、静态 SVG 和小型 WebP。无需新增运行时框架，功能回归风险最低。

### 路线 B：局部 Lit Web Component（决策门后可选）

只有满足以下任一情况才引入：

- 检查器即将增加批注、拖拽、对比或复杂局部状态。
- 原生模块拆分后仍难以控制重复渲染和状态同步。
- 后续会把更多独立区域逐步组件化。

不得在本轮直接整站迁移 React、Vue 或其他框架。

### 可选小工具

- Rough.js：只用于生成静态手绘 SVG，不建议作为页面持续运行依赖。
- Sharp：仅当 WebP/PNG 素材体积无法达标时再加入开发依赖。
- CSS 动效：优先于 GSAP/Motion；当前交互不需要重量级动画运行时。

## 8. 验收标准

- 功能测试、校验脚本全部通过。
- 右栏有明确的硬纸板、主纸页、活页环和分页标签四层关系。
- 纸纹在正常亮度下可感知，但不影响文字对比度。
- 装饰元素不与按钮、色票和 Prompt 抢视觉焦点。
- 长内容滚动时，章节导航仍清晰可用。
- 桌面端和移动端都存在真实内容截图，不用空白状态代替验收。
- 新增图片尽量小于 80KB；整组检查器素材目标小于 250KB。
- 不引入来源不明或授权不清的字体、纹理和插画。

## 9. 停止条件

遇到以下情况必须暂停并汇报，不能自行扩大范围：

- 需要整站迁移框架才能继续。
- 必须更改后端 API 或数据结构。
- 素材授权不明确。
- 原有功能测试出现无法解释的回归。
- 设计稿尚未确认却准备进入代码实现。
