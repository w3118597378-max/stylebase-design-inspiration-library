## 对素材生成的最终决定

允许并鼓励生成少量定制素材，因为纯 CSS 很难完全表现真实纸纤维、铅笔颗粒和手工不规则性。但必须采用混合实现：

### 必须由代码实现

- 检查器布局与滚动。
- 所有文字和按钮。
- 四个章节导航及当前状态。
- 桌面和移动端响应式。
- 键盘操作、焦点、ARIA、展开折叠和复制行为。

### 可以生成素材

- 512×512 无缝暖白纸张纹理，低对比，不含文字，WebP 目标 20–50KB。
- 透明铅笔颗粒、圈注、箭头和小型印章素材。
- 半透明胶带或纸边磨损纹理。
- 纸张 alpha edge mask。

### 优先使用 SVG 而不是位图

- 活页环。
- 纸夹。
- 分页标签轮廓。
- 需要随尺寸缩放的线条图形。

### 禁止

- 不要把整张侧栏生成成一张图片。
- 不要生成带文字的按钮或导航标签。
- 不要用位图承担点击区域、状态或响应式布局。
- 不要堆满咖啡渍、撕纸、贴纸和胶带。

## 第一次交付，只做这些

1. 启动现有项目并捕获一个有完整分析内容的右栏真实截图。
2. 解释当前为什么没有形成可信的纸张效果。
3. 从项目灵感库选出最相关的 3–6 张参考，只提取可复用的设计语言，不照搬。
4. 生成两套小型纸纹/手绘质感素材候选，并在独立样张上展示，不接入正式页面。
5. 基于其中更合适的一套，输出唯一一份桌面端与移动端高保真检查器设计稿。
6. 列出代码层和素材层分别负责什么、预计改哪些文件、如何验证功能不变。
7. 向用户展示设计稿和素材样张，等待确认。未经确认不要修改正式页面实现。

用户现在最需要的是一个可信、可见、可以确认的成品方向，而不是更多抽象计划。
